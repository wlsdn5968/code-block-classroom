- Node 버전: CI와 Vercel은 26으로 맞췄다(2026-11-12). 운영자 PC는 24.14.0이고 빌드·검사는 모두 통과한다.
- 개발 도구의 보안 경고 7건(minimatch, 중간 등급)이 남아 있다. typescript-eslint가 고친 판을 아직 받지 않아 지금은 올릴 수 없다. 사이트에 실리는 코드가 아니다. `npm audit`으로 가끔 다시 본다(보고서 25-4).
- TypeScript 7, ESLint 10은 검사 도구 부품이 지원하면 올린다(보고서 25-4).
- 이 PC에서 독립 검토 에이전트 2개와 브라우저 검사를 동시에 돌리면 검사가 시간 초과로 실패한 적이 있다. 무거운 검사는 혼자 돌린다.
- 원격(GitHub)에 이미 합쳐진 브랜치 24개가 남아 있다(2026-11-10. 로컬의 합쳐진 브랜치 16개는 지웠다). 지워도 되고(PR에서 복구 가능) 그대로 둬도 동작에는 영향 없다.

## 5. 일하는 순서 (2026-11-12 고침. 이유는 보고서 25절)

1. 상태 확인: `git status`, 열린 PR, 필요하면 실제 주소 검사.
2. 브랜치를 만들어 작업한다(main 직접 커밋 금지). **PR은 작게**: 기능 코드와 새 화면 문장은 되도록 나누고, 레슨 다시 쓰기는 2~3개씩.
3. 새 콘텐츠는 공식 문서 원문을 내려받아 인용(`evidence`)을 글자 그대로 대조한다. 초안을 쓸 때부터 쉬운 말 기준(기본 900자, 문장 60자)을 지킨다.
4. 타입 검사 → 문법 검사 → 빌드 → `test:parity` → `test:walk`. 화면은 Playwright로 찍어 직접 본다.
5. 독립 검토(낮은 등급 모델 에이전트, 읽기 전용). 콘텐츠는 "사실이 원문과 맞는가"와 "초등 고학년이 읽을 수 있는가"를 같이 묻는다 → 지적을 코드·원문에서 직접 확인하고 반영. 조건·예외를 더할 때는 "더 깊이 보기"에 넣는다.
6. 반영해서 바뀐 부분만 한 번 더 검토받는다(반영이 없으면 생략).
7. PR을 만든다. 화면 문장이 새로 생기거나 바뀌면 **자동 merge를 켜지 않고**, 재검토까지 끝낸 최종본을 미리보기·대조표와 함께 운영자에게 보고한다.
8. 승인되면: 문장은 더 고치지 않는다 → 승인 기록은 PR 댓글로 → merge → 실제 주소에서 확인.
9. `docs/content-port-report.md`에 절을 추가하고 이 파일을 갱신한다(문서만 바꾸는 PR은 화면 검사를 건너뛰어 빨리 끝난다).

보고할 때는 한 일·검증·확인하지 못한 것·운영자가 할 일(무엇을, 왜, 안 하면, 급한지, 누를 버튼)을 쉬운 말로 적는다.
